Koneksi Supabase

Sinkronisasi delta otomatis dan Supabase Realtime untuk SATRIA Framework 3.0
Penting — kontrol scope baru: Admin dapat membaca/mengganti snapshot organisasi penuh. Operator dan Viewer wajib memakai RPC server yang mengembalikan proyeksi allowlist berdasarkan assignment OPD dan tahun; akses langsung ke snapshot ditolak RLS. Operator hanya dapat menyimpan record dalam scope-nya. Terapkan semua migrasi keamanan dan deploy fungsi terkait sebelum mengandalkan pembatasan ini. JSON snapshot masih merupakan jembatan kompatibilitas; migrasi ke tabel bisnis terstruktur dengan RLS per record tetap menjadi sasaran arsitektur jangka panjang.
Unduh salinan HTML berkonfigurasi agar URL, anon key, dan UUID tertanam di file. Siapa pun yang menerima file dapat melihat publishable/anon key; akses data tetap wajib dibatasi RLS. Jangan pernah memasukkan `service_role` atau secret key.
Ingat login di perangkat ini: SATRIA akan memulihkan sesi Supabase secara otomatis setelah Anda masuk sekali. Kata sandi tidak disimpan. Jika memilih Keluar, akun dicabut, atau data situs dihapus, Anda perlu login kembali. Aplikasi dari ikon Layar Utama iPhone memiliki penyimpanan terpisah dari Safari.
Atur kata sandi baru

Panel ini muncul setelah tautan pemulihan Supabase dibuka. Pilih kata sandi baru yang kuat dan jangan gunakan ulang kata sandi lama.

SATRIA mengingat sesi Supabase di HP ini selama masih berlaku. Gunakan tombol Keluar untuk mengakhirinya.

Jika muncul “Invalid login credentials”: pastikan akun email ada di Supabase Dashboard → Authentication → Users pada project yang tertanam di file ini, lalu cek kata sandinya. Organization UUID tidak menentukan validitas email/kata sandi. Jika akun belum ada, buat akun Auth terlebih dahulu; setelah login berhasil, akun juga harus memiliki membership aktif pada organisasi ini.
Prosedur: siapkan project staging → jalankan file SQL pendamping satria-supabase-staging-bootstrap.sql setelah ditinjau → buat akun Auth → bootstrap organisasi dan membership admin melalui SQL Editor → masukkan URL, publishable/anon key, dan UUID organisasi → login → tarik atau kirim snapshot. Ekspor backup lokal terlebih dahulu. Konflik versi tidak ditimpa otomatis. Simpan/unduh backup lokal, tarik versi cloud terbaru, lalu terapkan kembali perubahan yang memang diperlukan.

Persiapan database

Untuk pemulihan kata sandi, alamat halaman SATRIA harus diizinkan di Supabase Dashboard → Authentication → URL Configuration → Redirect URLs. SQL bootstrap disediakan sebagai file terpisah dari HTML. Perubahan disimpan otomatis sebagai delta per record setelah Anda menyimpan data. Supabase Realtime memberi tahu pengguna lain tentang versi baru; data yang diterima tetap dibatasi scope server. Tombol Sinkronkan perubahan menjalankan sinkronisasi perubahan yang tertunda. Full snapshot hanya untuk bootstrap/pemulihan Admin yang dilakukan secara eksplisit. Konfigurasi juga dapat disimpan di browser melalui tombol Simpan konfigurasi. Saat file yang sama dibuka kembali pada browser/profil yang sama, URL, publishable/anon key, dan Organization UUID akan diisi otomatis. Kata sandi tidak disimpan. Gunakan Unduh HTML dengan konfigurasi bila ingin membawa konfigurasi bersama file ke browser/perangkat lain; file tersebut memuat publishable/anon key sehingga bagikan dengan bijak.
